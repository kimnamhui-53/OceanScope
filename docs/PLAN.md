2025 보고서 서식을 그대로 유지한 **2026 동해 소용돌이 분석보고서.hwp**를 생성한다.

## 1. 전체 아키텍처 — 5단계 파이프라인

```
[1] 데이터 다운로드 → [2] 그래프 36장 생성 + 소용돌이 통계 → [3] 수치 분석
      → [4] 코멘트 생성(템플릿+LLM) → [5] HWP 조립(서식 유지)
```

모든 단계는 독립 모듈로 만들고 `build_report.py`가 순서대로 호출.
중간 산출물은 `output/2026/` 아래에 저장해 실패 시 해당 단계만 재실행.

### 1단계: 데이터 자동 다운로드 — `download_data.py`

Copernicus Marine Toolbox의 Python API(`copernicusmarine.get()`, "get original files" 방식)를 사용.

- **SLA/해류**: `SEALEVEL_GLO_PHY_L4_NRT_008_046`
  → 원본 파일 `nrt_global_allsat_phy_l4_YYYYMMDD_*.nc` (현재 스크립트가 읽는 파일명 그대로)
- **수온**: `SST_GLO_SST_L4_NRT_OBSERVATIONS_010_001` (OSTIA)
  → `YYYYMMDD120000-UKMO-L4_GHRSST-...-OSTIA-GLOB-*.nc`
- 사용법: `copernicusmarine.get(dataset_id=..., filter=f"*{yyyymmdd}*", output_directory="data")`
- 최초 1회 `copernicusmarine login` (계정 무료)

**결정 필요 ①: 월 대표 분석일 규칙** — 2025 보고서의 각 월 그림 날짜를 확인해
같은 규칙(예: 매월 15일 또는 말일)을 적용. 챕터1 "분석날짜"도 이 규칙으로 자동 치환.

**중요 리스크: NRT 상품은 보존기간이 지나면 서버에서 삭제됨.**
2026년 말에 1~3월 자료를 소급 다운로드하지 못할 수 있음.
→ 대응: (a) 매월 자동 다운로드를 Windows 작업 스케줄러에 등록해 미리 적재,
(b) 없는 과거 월은 재처리 상품(`SEALEVEL_GLO_PHY_L4_MY_008_047`, OSTIA REP)으로 폴백하는 로직 포함.

### 2단계: 그래프 생성 — 기존 스크립트 리팩토링

- 세 스크립트의 공통부(지도 범위, 라벨, 지명, 로고)를 `map_common.py`로 분리
  (이미 `mmap_style` 모듈 흔적이 __pycache__에 있음 — 있으면 재활용)
- 각 스크립트를 `run(yyyymmdd) -> 결과` 함수로 변환 (argv/하드코딩 날짜 제거)
- `eddy_tracking.run()`은 **`{"w": 난수성, "c": 냉수성, "w_c": 울릉도·독도 난수성, "c_c": 울릉도·독도 냉수성}`를 반환**하고
  `output/2026/eddy_stats.json`에 월별 누적 저장 → 표1과 코멘트의 단일 소스
- 위 0절의 버그 3건 수정, 저장 파일명 규칙 통일:
  `WA_Method_YYYYMM.png`, `eastsea_current_YYYYMM.png`, `eastsea_temp_YYYYMM.png`
- 산출물: 12개월 × 3종 = **36장** (분기당 9장)
- 참고: dpi=800 + 이중 contour 루프라 1개월 처리에 수 분 소요 → 12개월 배치는
  수십 분 각오. 필요 시 dpi 300으로 낮추는 옵션 제공(HWP 삽입용으론 충분)

### 3단계: 수치 분석 — `analyze.py` (todo.txt 5번 반영)

코멘트에 넣을 정량 근거를 자동 산출:
- 소용돌이: eddy_stats.json 그대로 사용
- 해류: 동해를 구역(동한난류역, 북한한류역, 외해 등)으로 나눠 구역 평균 유속을
  주변과 비교 → "○○ 해역에서 상대적으로 강한 흐름" 판단 플래그
- 수온: 월별 min/max, 영역 평균, 등온선(수온전선) 대략 위도 산출
  → "수온전선이 북위 ○○도 부근에 형성" 류 문장의 입력값

### 4단계: 코멘트 생성 — `comments.py`

**두 층으로 분리** (숫자 정확성과 문장 자연스러움을 분리):

1. **고정 템플릿 (LLM 미사용)** — 소용돌이 개수 문장은 f-string으로 확정 생성:
   > "동해에 나타난 소용돌이는 난수성 {w}개, 냉수성 {c}개이며, 울릉도‧독도
   > 주변해역에 나타난 소용돌이는 난수성 {w_c}개, 냉수성 {c_c}개이다."
2. **LLM 서술 코멘트** — 사전 작업으로 2025 보고서에서 월별 코멘트 전체를 추출해
   `templates/comment_corpus_2025.md`로 저장(1회). 프롬프트 = "이 문체·용어(수온전선,
   난수성 소용돌이, 동한난류, 북한한류)를 유지하며 아래 이번 달 수치에 맞는 요약 작성"
   + 3단계 분석값. 어느 달 문장이든 스타일 소스로 활용(사용자 요구 5번).
   생성 후 개수 등 숫자가 stats와 일치하는지 자동 검증.

**결정 필요 ②: LLM 실행 방식**
- **1안(권장, 추가 비용 0)**: 보고서 생성을 Claude Code 스킬(`/eddy-report 2026`)로
  실행 — 코멘트 작성·검수를 지금 이 Claude가 구독 요금 안에서 수행. API 키 불필요.
- 2안: `claude-haiku-4-5` API 호출로 완전 무인화 — 연 1회 실행이면 비용 몇십 원 수준.
- 3안: LLM 없이 템플릿 치환만 — 무료·완전자동이지만 문장이 기계적.

### 5단계: HWP 조립 — `assemble_report.py` ★ 가장 큰 작업

2025 hwp를 템플릿으로 쓰되, 방식은 두 가지 중 결정:

**A안 — 한컴오피스 풀버전 + pyhwpx(COM 자동화)** ← 서식 보존 최우선이면 권장
- 2025 hwp를 열어 → 표지 날짜 치환("2025. 12." → "2026. 12.") → 챕터1 분석날짜
  치환 → 각 월 그림 개체를 새 PNG로 교체 → 코멘트 문단 교체 → 표1 셀 값 입력
  → "2026 동해 소용돌이 분석보고서.hwp" 저장
- 장점: 서식·규격 100% 보존(요구 1번), 그림 크기/배치 원본 그대로
- 단점: **이 PC에 한컴 풀버전 설치 필요**(현재 뷰어만 있음), 실행 시 한/글 창이 뜸
- 안정화 팁: 치환 지점을 찾아바꾸기 대신 **누름틀(필드)** 로 한 번 심어두면
  이후 매년 완전 무인 실행 가능

**B안 — hwpx(XML) 직접 조작** ← 한컴 설치가 어려우면
- 1회 수동: 한글이 설치된 다른 PC에서 2025 hwp를 `.hwpx`로 저장
- 이후: hwpx는 zip+XML이라 Python 표준 라이브러리만으로 텍스트 치환·
  BinData 이미지 교체 가능 → 서버/스케줄러에서도 무인 실행
- 단점: XML 구조 분석 초기 비용, 최종 산출물이 hwpx(한글에서 hwp로 재저장 가능)

C안(hwpx 신규 생성)은 서식 재현이 어려워 **비권장** — 요구 1번 위배 위험.

※ 챕터1 본문·향후 개선사항(요구 3, 7번)은 원본 유지이므로 어느 안이든 손대지 않음.

## 2. 오케스트레이션: AI agent vs n8n

**권장: Python 파이프라인 + Claude Code 스킬** (`.claude/skills/eddy-report/`)
- 결정적(deterministic) 작업(다운로드·그래프·통계·HWP 치환)은 전부 Python이 수행
  → 재현 가능, 숫자 오류 없음
- LLM이 필요한 곳(코멘트 작성, 데이터 결측 같은 예외 상황 판단)만 agent가 담당
- 실행: `claude` 실행 후 `/eddy-report 2026` → 파이프라인 호출 + 코멘트 작성 + 결과 검수

**n8n 비권장 이유**: cartopy·netCDF·HWP COM 등 로컬 의존성이 무거워 n8n 노드로
감싸도 결국 로컬 Python을 호출하는 셔틀 역할뿐. 유지보수 지점만 늘어남.
정기 실행이 필요한 건 "매월 데이터 미리 받기" 하나인데, 이는 Windows 작업
스케줄러 + `download_data.py`로 충분.

## 3. 실행 순서 및 예상 규모

| 순서 | 작업 | 규모 |
|---|---|---|
| 0 | 결정 2건: 월 대표일 규칙 확인, HWP A/B안, LLM 방식 | 즉시 |
| 1 | copernicusmarine 설치·로그인 + `download_data.py` (NRT/폴백 포함) | 반나절 |
| 2 | 스크립트 3종 함수화 + 버그 수정 + `eddy_stats.json` | 반나절 |
| 3 | 2025 보고서 코멘트 코퍼스 추출 + `analyze.py` + 템플릿/프롬프트 | 반나절~1일 |
| 4 | HWP 조립 모듈 (A안 또는 B안) | 1~2일 ★최대 작업 |
| 5 | `build_report.py` 통합 + 2025년 데이터로 리허설(2025 보고서와 대조 검증) | 반나절 |
| 6 | (선택) 매월 데이터 적재 스케줄러 등록, Claude Code 스킬화 | 반나절 |

검증 방법: 5번에서 **2025년 날짜로 파이프라인을 돌려 기존 2025 보고서와 비교**
— 그림·개수·표가 재현되면 파이프라인 신뢰 확보 후 2026에 적용.
